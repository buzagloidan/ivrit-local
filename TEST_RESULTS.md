# Validation — 0.2.0 beta

16 October 2026, Apple Silicon Mac. This is measured development evidence, not a store
approval, broad accuracy evaluation, vulnerability certification, or native Windows Chrome test.

## Automated production-code checks

`npm test` exercises the real panel/setup/background and pure file/transcript modules with
mocked browser APIs. Passing cases include:

- Microphone permission setup, cancellation, denial, trusted handoff, direct already-granted capture.
- Browser-tab picker gesture timing, no microphone mixing, disabled video, continuing playback flags,
  silent/audible feedback, source rejection, track-end/Stop cleanup and failure recovery.
- Temporary insertion access first; explicit per-site grants; separately checked all-site opt-in;
  sender/session/tab/window validation, revocation plumbing, cancellation and Undo routing.
- Caption timestamp formatting and escaping; malformed/nonmonotonic cues; opt-in draft storage,
  seven-day expiry, corruption handling and bounded retention.
- File size/duration validation and media URL cleanup without full-file `decodeAudioData` allocation.

## Real model and endurance

The production worker, official sherpa-onnx 1.13.7 WASM and bundled unchanged Hebrew INT8 model
ran locally with network fetches forbidden by the harness.

- New CC0 demo, 2.8507 seconds including padding: “שלום.”, about 0.25 seconds recognition time.
- Recognizer-derived cue: approximately 0.92–1.54 seconds for the greeting.
- Fresh silent stream after speech returns no prior text.
- 1,800 seconds of repeated CC0 greeting plus silence: 150 segments, 101.42 seconds processing.
- Fixed 512 MiB WASM heap; observed Node RSS peak approximately 669 MiB, settling near 300 MiB
  toward the end. No growth above the first post-warm-up sample; no runtime exhaustion or state leak.
- Raw endurance measurements: docs/endurance-0.2.0.json. This is not a guarantee for low-memory
  computers or continuously complex/noisy speech. Real capture still requires acceptance checks.

## Browser evidence

- Production file-player → AudioWorklet → speech-worker pipeline ran in the in-app browser and
  actual desktop Google Chrome, using the CC0 sample under the manifest CSP. Returned “שלום.”
  and enabled timed caption export. Files played silently and completed normally.
- Adversarial fixture: scripted click and Enter cannot insert; hidden/password destinations remain
  unchanged; cancellation, oversized transcripts and untrusted senders are rejected.
- Real browser input: visible-field click inserts; trusted Enter replaces a selected textarea range;
  contenteditable receives literal `<script>` text without creating executable markup; Undo restores
  the earlier field value. No Enter/form submission is generated by the extension.
- Opt-in local draft survived a reload with text and cues; Delete draft disabled recovery while
  retaining the current visible transcript. English/Hebrew UI switching verified.
- Earlier browser test: 48 kHz stereo MediaStream resampled through the 16 kHz production worklet.
- Responsive layout checked at 280/320/360/480 CSS pixels; new English/Hebrew UI rechecked for the release.

## Release integrity

- Model encoder/decoder/joiner SHA-256 and tokenizer Git-blob digest match pinned upstream data.
- Runtime archive and WASM binary are pinned. Build assets are verified before packaging.
- Current demo provenance is CC0, with original SHA-1; Apple-generated demo is excluded from release.
- Release packager rejects unexpected files, validates resources/CSP and tests ZIP integrity.
- Code/license/privacy/support and dependency inventory are included in the repository.

## Remaining manual gates

Browser automation refuses Chrome's internal extension-settings URLs. No workaround was used.
The installed extension reload/service-worker/side-panel flow, native microphone/tab-sharing dialogs,
actual Windows Chrome, physical-microphone/speaker conditions, screen readers, low-memory devices,
and Chrome Web Store publisher 2FA remain manual acceptance gates in docs/ACCEPTANCE.md.
CI unit checks on Windows are useful but do not constitute native Windows capture testing.
Browser download observation stalled, so native TXT/SRT/VTT download completion remains a manual check; generated caption content and formatting passed module tests.
The extension has not been submitted to the Chrome Web Store.
